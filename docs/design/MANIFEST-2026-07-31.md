## The headline

**Item 1 is not a deletion, and it is close to the cheapest item in the round.** "Provenance" is three
things wearing one costume: field paths (→ a trace mode, off by default, one keystroke on), caveats
(→ stay visible, rewritten to human phrases), and developer notes (→ never render). The
no-fabrication rule lives entirely in the second class and is untouched.

**The current design already is trace-on** — every path is placed, styled and correct. The work is a
visibility condition and a keystroke, not new UI.

## Three findings the brief did not name

1. **The app is rendering its own instructions.** The card prints *"SUPPRESS this row in the UI while
   evaluative_adjustment_available is false"* as body text, above a row reading `±0` against `±0`.
2. **The assistant prints the model's context keys inline, mid-sentence** — `[page.next_pick_reference]`
   and five more, plus a `model prose over context:` footer. Removing those reclaims real height
   before the container is touched.
3. **At 1180 the rankings pane has no PLAYER column at all.** Rows identify by `RB10` alone. This is
   the strongest possible answer to "may need to be wider" — it is not a preference, the pane is
   dropping the one column that identifies the row.

## Sequence

**1 before 2, 4 and 6.** It removes the class-1 text from the assistant prose, frees the card height
item 2 reorders, and buys the pane width item 6 needs. Doing the others first means designing around
text that is about to leave.
