## Request
Consensus as an adjustment to bottom-up, not a rival

> "I like having the consensus adjust as well, we should at some point when we finish bottom up, see
> which is better"

Founder's own words, 2026-07-29. Escalated by the strategist because it conflicts with a project rule.

## Why it matters

**It contradicts `CLAUDE.md` §4**, which says ranking sources stay separate and are **never blended**
— so our model's independent view stays visible against consensus rather than silently converging
toward it. The founder's preferred product shape is a blend. **Measuring one is fine; shipping one
needs the spec amended, and that is his call, not an agent's.**

## Initial read
**Measuring is already registered** — PR-004 §11 tests it as a nested, out-of-sample question rather
than a three-way leaderboard, because a blend containing consensus beats consensus in-sample by
mechanical identity and that number would mean nothing.

**Shipping it is the open decision.** The strategist's middle path, on the record: **consensus adjusts
display and confidence, not the score.** That keeps the independent view visible — which is what §4
was protecting — while letting consensus do the thing the founder actually wants it to do.

Do not treat this as settled by the measurement coming back favourable. The rule exists to stop
silent convergence on the market, and a good blend score is exactly when that risk is highest.
