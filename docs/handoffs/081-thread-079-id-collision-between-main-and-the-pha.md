## Why

CLAUDE.md already records this exact failure for threads 043, 049, 053 and ADR-048, and says
IDs must come from `tools/handoffs.py new`/`sync` only. This is a fourth instance, which
suggests the guidance is not sufficient on its own.

The mechanism is worth noting for whoever fixes it: `sync` allocates the next ID from the files
it can see. A worktree holding an unsynced thread on disk is invisible to a `sync` run in the
main checkout, so both allocate the same number independently. Parallel worktrees make the
documented protocol insufficient rather than merely easy to forget — the protocol assumes a
single namespace, and worktrees create several.

Worth deciding alongside the fix: should `sync` scan sibling worktrees under
`.claude/worktrees/*` before allocating, making the collision structurally impossible rather
than a rule agents must remember?
