## Ask

FR-069's full scope has two parts. This session (`docs/handoffs/089-...md` reply, commit `65c8047`)
built the part that's frontend-only: the LEAGUE-SETTINGS-BOUNDARY.md boundary rule inside a real
Settings panel (`ui/components/shell/SettingsPanel.tsx`) for whichever league is already selected.

**Not built, and it's yours, not frontend's:** the founder's actual request --

> "the drop down should show 4 league options - my three leagues and 'custom' ... if custom is
> selected, pop open a pane to ask me for the inputs."

Concretely:

1. **Retire the 24-preset matrix.** `src/generate_config_matrix.py` and the 24 `data/export/<preset>/`
   directories go. `frontend/ui/data/league-registry.ts` already reads whatever `_leagues.json` lists
   (generated by `sync-exports.mjs` from `data/export/*`) with no hardcoded preset list on the
   frontend side -- so once the backend directories are gone, the dropdown shrinks to whatever's left
   with zero frontend changes. Verified this session: the switcher has no knowledge of "24" anywhere,
   it just enumerates directories.
2. **`src/league_builder.py` becomes the primary path**, not a fallback, for the third
   (still-uncaptured, FR-052) league and any future "Custom" submission.
3. **The Custom pane's own scoring question**, per FR-040's costing doc (`docs/specs/FR-040-custom-
   league-settings-costing.md`, thread 089): does selecting Custom trigger a real rebuild (a job
   this session's static-hosting deploy has no queue for -- see 089 point 1), or does the founder run
   it locally and the hosted site only ever shows already-built custom leagues? **Design and backend
   should settle this** (FR-069's own text says the same). Frontend's `SettingsPanel.tsx` is built to
   extend cleanly either way (it already refuses to accept a scoring edit it can't apply -- same
   pattern would extend to a Custom pane).

## Why

Without this, `_leagues.json` keeps listing 24 synthetic leagues nobody plays in, and the dropdown
stays the "list of hypotheticals with his real leagues buried among them" the founder specifically
objected to. The frontend boundary rule (this session's work) has nothing to attach to until the
preset matrix is actually retired and/or a Custom submission path exists to build against.
