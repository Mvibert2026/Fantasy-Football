## Ask
Threads 017 (pm) and 039 (frontend spec) are implemented. Two new files now exist under
`data/export/` (unprefixed path only — not per-league, not part of the 24-config matrix):

- `data/export/weekly_finishes.json` (9.3MB, 1481 players)
- `data/export/season_stats.json` (2.3MB, 1481 players)

Built by new `src/export_history.py`. **Not part of `CONTRACT_VERSION`** — like
`player_descriptions.json`, they carry their own `export_version: "1.0.0"` and are generated by
their own script (`python src/export_history.py`), not by `export_contract.py`/`export_static.py`.
`CONTRACT_VERSION` in `src/export_contract.py` is bumped `1.8.0` -> `1.9.0` anyway per thread
039's ask, purely as a marker that these two files now exist — no existing field in any
`CONTRACT_VERSION`-tagged artifact changed shape.

Exact shapes documented in `docs/data-contract.md` (new section right before
`player_descriptions.json`'s, same doc). Short version:

- `weekly_finishes.json`: `players[].seasons["<year>"] = {target_data_unavailable, weeks: [{week,
  finish, bye}]}`. `finish` uses SQL `RANK()` (ties share a rank, next skips). `bye: true` is
  schedule-derived; `finish: null, bye: false` means no recorded stat line that week (see the
  file's own `no_row_semantics_note` for the exact honesty caveat — it is NOT a confirmed
  inactive/roster-status lookup, just "no row").
- `season_stats.json`: `players[].seasons[] = {year, games, targets, target_data_unavailable,
  receptions, receiving_yards, receiving_tds, rushing_yards, rushing_tds, fantasy_points_ppr}`.

**Hard constraint honored:** seasons 2003-2008 carry `target_data_unavailable: true` and
`targets: null` in both files — never a fabricated `0`. Verified directly against `data/nfl.db`
before writing the constant (league-wide `SUM(targets)` collapses to single digits for those six
seasons vs 16,000+ adjacent) — see `export_history.py`'s module docstring.

**Player universe:** `player_id`s with >=1 row in `player_weekly_stats` for `season >= 2018` at
QB/RB/WR/TE (matches the board population; no K/DEF stats exist in this project). Season detail
rows for an included player go back as far as their own history in the table.

**2025 is included** (current-season display, e.g. `seasons["2025"]`). This is historical fact
display, not a ranking-model input, so `holdout.py`'s lock (which governs model *selection*) was
judged not to apply — reasoning is spelled out in `export_history.py`'s docstring. Flagging this
explicitly since it's a judgment call on a CLAUDE.md guardrail, not a silent decision.
