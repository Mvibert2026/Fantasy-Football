# Fable workflow review — 2026-07-27

**Highest-leverage change, one sentence:** take number-allocation and shared-document writes out of
every writer's hands — threads authored by slug with IDs assigned mechanically at sync, the PM
writing through a staging directory instead of directly into the mailbox, per-session status files
instead of one append-only log, and the build-state table generated by `tools/state.py` — which
eliminates both demonstrated silent-loss classes (ID-collision overwrite, stale-bridge force-write)
and the only real write contention the system has, while *removing* PM work rather than adding
process.

## 0 · Corrections to the mandate's description of the system

The mandate asked for its own description to be checked. Three claims are wrong or stale, and two
matter.

1. **"No worktree or branch isolation — every agent works in the same checkout concurrently" — no
   longer true.** `git worktree list` shows three agent worktrees under `.claude/worktrees/`

   rest of the system. So worktree isolation is not a proposal to evaluate; it is a live mechanism
   with a missing integration step. The question B answer changes accordingly (§B below).

2. **"A collision occurred at `053`, caught by luck" — an undercount by at least 3×.** The git log
   records collisions as an ongoing class, all within ~24 hours, in **two namespaces**:
   - Thread ID 043: `3248f79` — "A concurrent session's new 043-draft-mode-gap-list.md collided…"

   PM-vs-agent bridge quirk; it is the allocation scheme.

3. **The announced fix for failures 1–2 is structurally broken.**

4. Minor: `docs/handoffs/README.md:74` lists roles `pm, backend, frontend, data-ops, strategist,
   design, founder`; the tooling accepts `researcher`, `librarian`, `fable` as well

5. Minor: `OPEN.md` shows negative thread ages (`-1d`, e.g. lines 36-44) — the PM's bridge writes
   `OPENED: 2026-07-27` while the local clock says 2026-07-26. Two clocks disagree about "today."
   Cosmetic now; it becomes real if staleness thresholds ever tighten. Fixed for free by W1
   (the tool stamps `OPENED` at sync).

   051's resolution was *not* a bare self-report. The reply

## A · Where does it break, and at what N?

**The binding constraint at twenty agents is the pair of PM sequencing capacity and the shared
write-back documents — in that order — not `src/` boundaries, not the ID namespace, not the single
checkout.**

Evidence:

- `src/` boundaries held perfectly at N=9 (mandate, failure 7) and the file-ownership map in
  `.claude/agents/*.md` is clean (backend owns `src/`+`tests/`, frontend owns `frontend/`,
  data-ops owns ingestion). Code contention is not the constraint and worktrees (§B) retire it
  permanently.
- The write-back protocol (`CLAUDE.md` "Write back, every session"; `operating-model.md:58-63`)
  routes **every** agent, every session, through `docs/CURRENT-STATE.md` (in-place edit),
  `docs/status.md` (append), `docs/founder-requests.md` (append when triggered), and
  `docs/handoffs/OPEN.md` (regenerate). Two of nine agents nearly collided on `CURRENT-STATE.md`
  (mandate, failure 7). At twenty agents this is a guaranteed serialisation point: 20 concurrent
  in-place editors of one file is a merge storm under worktrees and silent last-writer-wins
  without them.
- PM throughput already degraded visibly at N=9: 42→64 threads in a day with ≥8 overlapping pairs,
  most PM-authored (mandate, failure 9; `pm-operating-discipline.md` cause 3); two stale-cache
  misreports asserted as repository fact (062 RETRACTION, `050-sprint-3-runbook.md:20`); a
  100k-token verification from over-specification (failure 8). The PM is a single sequential
  writer whose error rate rises with round size. Twenty agents ≈ 2.2× the thread volume that
  already produced eight duplicates.
- The ID namespace breaks *before* twenty (it broke at nine, four times in a day) but it is the
  cheapest thing on the list to fix outright (W1), so it is not the ceiling — it is the first
  work order.

**Cheapest thing that raises the ceiling:** ranked-table items 1 + 2. Together they remove the
mailbox's write contention, the shared-log contention, and the PM's ID bookkeeping — after which
the constraint is purely how many well-formed, non-overlapping threads the PM can specify per
round, which item 4's `DELIVERED` flow and M3's pre-dispatch pass stretch but do not remove. See
"Stated ceiling" at the end.

## B · What should be structurally impossible rather than detected?

### Single ID allocator — **adopt, but not the version on record**

The RECONCILIATION range-partition rule is broken on arrival (§0.3). The mandate's own sketch —
"threads are written by slug and the tooling assigns the next free ID atomically at sync" — is the
right shape, and it kills failures 1 and 2 at the root rather than partitioning around them:

- Authors (PM included) create `NEW-<slug>.md`. Nobody types a number, so nobody can collide on
  one, and a bridge write cannot target an existing numbered file because it never writes a number.
- `handoffs.py sync` — which every session already runs — renames `NEW-*` files to the next free
  ID, stamps `OPENED` (fixing the clock skew of §0.5), and refuses to overwrite. Allocation is
  atomic because sync runs in one process on one machine.
- Cross-references written before allocation use the slug; sync can leave them (slugs stay in the
  filename) or patch them. Numbers remain for human conversation, which is what they are for.

Honest cost: in-flight references to "the thread I just wrote" are by slug until the next sync;
`new` already exists so agents lose nothing. One backend session. **Nothing cheaper works:** the
range rule is free but broken; "be careful" is what already failed four times in a day.

Extend the same principle to ADR numbers (W2) — same failure, same fix, demonstrated by `1140586`.

### Worktree/branch isolation — **already happening; formalise the missing half**

The evaluation the mandate asked for is moot in one direction: worktrees exist and are in use
(§0.1). What does *not* exist is the integration step — branch `worktree-agent-a254f18ab4bde998e`
holds a finished, unmerged data-ops commit that no inbox, index, or check surfaces. Worktrees
without a merge owner convert "silent overwrite" into "silent non-delivery," which is quieter, not
safer.

Formalisation (W9): code-writing agents run in worktrees by default; a single integrator (the
session that runs closeout, or the PM's round-end step) merges agent branches to `master`
one at a time; `handoffs.py check` gains a warning when a `worktree-agent-*` branch is ahead of
`master`. Boundary violations then surface as merge conflicts — detection for free — and **PM
file-boundary assignment can be deleted from thread templates for code work**, which is the
removing-PM-work outcome the mandate hoped for. Keep boundaries only for the shared docs until
item 2 lands, after which they matter far less.

Honest cost: someone merges. At the current commit cadence (39 and 58 commits/day) merges are
small and conflicts near-zero once the shared docs are de-contended. Reject the heavier variant
(PR review per branch): nothing in the evidence justifies review gates on top of the existing
verifier conventions, and the mandate is right that safer-and-slower fails.

### One more candidate the mandate did not list: **make the PM's destructive write impossible**

Failure 5's damage vector is not that the PM *read* a stale cache — it is that the PM can *write*
into `docs/handoffs/` on the basis of one. The bridge is already write-blocked from `.claude/`
"for safety" (`010-install-agent-definitions.md:13`). Extend the same block to `docs/handoffs/`
and give the PM `docs/pm-outbox/` as its only write surface; sync ingests outbox files as
slug-threads (W1). The PM's stale view can then waste its own time but can no longer destroy an
agent's thread — structural impossibility, in exactly the strategist-Bash mould, and it costs the
PM nothing but a directory name.

## C · Is a directory of markdown files the right substrate?

**Yes — with one semantic change. The substrate survived the attack; the mutation rules did not.**

What the evidence supports keeping: durable, greppable, diffable, human-readable by the founder,
zero infrastructure, and it demonstrably carried nine concurrent agents with zero `src/` losses.
The alternatives fail the constraints: a SQLite mailbox or local queue loses greppability, git
history, and founder readability, and adds a writer-lock problem of its own; GitHub Issues et al.
require the remote and network the project does not have; both are rewrites of a working system to
prevent failures that cheaper changes (W1, W5) already kill. **Reject.**

What the evidence convicts:

- **Parse-by-regex fragility.** Three resolved threads registered as "RESOLVED with no reply"
  because their reply headings drifted from `### role ·` to `## Reply — role` (`5302fc0`). The
  check caught it — good — but the protocol's correctness rests on heading punctuation. Cheap
  hardening, not replacement: `new` templates the reply heading; `check` warns on
  reply-shaped-but-unparsed lines (W10, minor).
- **In-place mutation has no versioning semantics.** Thread 062 was rewritten in place to cut
  scope; thread 065 was then written against the *pre-cut* version — its "Done looks like"
  (065:33-38) demands the backlog tripwire, the OPEN.md staleness check, and the README amendment
  that 062's current text explicitly cuts (062:83-88). The mailbox's own coordination layer
  reproduced failure 10. The substrate is fine; edited-after-dispatch threads are the bug. W5
  makes dispatched thread text immutable-plus-amendments, which fixes this *and* is the answer
  to F.

## D · What replaces "an agent said it was done"?

The 051 evidence (§0.6) narrows this question usefully: the implementer's evidence was as good as
implementer evidence gets — tests, live DOM checks, honest disclosure — and the founder still
found the regression. The gap was in the **ask**, not the report: nobody enumerated "a pick is
committed → does not open," which is the founder's actual loop. Thread 063 then did exactly that
(nine-row trigger table, one test per row) — the project already invented its own fix and has not
generalised it.

**The cheapest acceptance signal that would have caught 051:** an enumerated trigger/behaviour
table in "Done looks like" for any thread about observable behaviour, written by the originator,
with evidence (test or DOM assertion) required *per row* before `RESOLVED`. Cost: minutes at
authoring time, paid by the person who knows the founder's workflow. It converts "done" from a
judgement into a checklist diff.

**Does it generalise beyond UI?** Yes, because the failure mode does: "done" claims fail where the
*requester's* scenario space is larger than the *implementer's* test space. The same table for a
pipeline thread is row-per-edge-case (empty input, stale `as_of_date`, missing join key); for an
export thread it is row-per-null-state. The existing evidence standards
(`operating-model.md:33-44`) say what *kind* of artifact counts; the table says *which cases* the
artifact must cover. They compose.

**The structural half (W6):** split `RESOLVED` into `DELIVERED` (set by the doer, with evidence)
and `RESOLVED` (set by the originator after reading the evidence against the table — for
founder-observable behaviour threads only). README rule 6 currently gives resolution to the doer
(`README.md:32-33` — "Only the `TO:` role may set `STATUS: RESOLVED`"), which for PM→agent threads
means the implementer accepts their own work; that is precisely how 051 closed green. Restricting
the two-step to behaviour threads keeps the added touch off the high-volume code/infra path, so
the throughput cost lands only where the founder was being used as the sensor — the one place the
mandate's own standard says the spend is justified. Code/infra threads keep single-step
doer-resolve with artifact evidence, unchanged.

Rejected as not cheapest: a standing verifier agent per thread (doubles session count for a
failure class the trigger table catches), and screenshot-gating everything (the sandbox provably
can't always produce one — 051 said so honestly; M2's third option already handles it).

## E · Is the PM a bottleneck, a single point of failure, or both?

**Both, and the documents agree once read as evidence rather than advocacy.** The PM's own
discipline doc (`pm-operating-discipline.md`, causes 3-5) concedes the duplicate threads, the
absence of self-audit, and "the PM is the least-checked component in the system." The mandate adds
that the PM was wrong about the repository twice (062 RETRACTION; `050:20`). Failure 9 (42→64
threads, eight dupes) and failure 8 (a 100k-token instruction) are both PM-authored costs.

What of the PM's job should be mechanical — each item with its existing vehicle:

| PM task today | Should be | Vehicle |
|---|---|---|
| Picking thread IDs | Mechanical | W1 (sync allocates) |
| Writing threads into the mailbox | Mechanical filing | W1 (outbox → sync ingests) |
| Regenerating OPEN.md | Already mechanical | `handoffs.py sync` |
| Verifying repo state before asserting it | Mechanical | `tools/state.py` (exists, built for exactly this — failure 5 and 8's answer) |
| Duplicate/contradiction screening | Semi-mechanical | 062 Part 2 detector (in flight) + M3's five-minute pass |
| Deciding what counts as verified | Stays PM, but table-driven | W6 trigger tables |
| Sequencing rounds, priority, founder interface | Stays PM | — the irreducible core |

**Would fewer, larger threads do?** No — the evidence runs the other way. Batching closeout failed
twice (`050:76`); bundled threads are what README rule 3 exists to prevent; and the duplicate
pairs came from *writing without reading the open set* (M3), not from threads being too small. The
one supportable coarsening: runbook-style umbrella threads for a round's sequencing (050 works)
with child threads per subject — already the de facto pattern.

**Should agents open more of their own work?** Yes, and it already works when tried: 065
(librarian → backend) is a correctly-formed agent-opened thread that moved a stalled build to an
owner without PM involvement. W1 makes this safe at volume (no ID to mis-pick). The PM's
round-open then becomes triage of an inbox partly filled by agents, not sole authorship of the
backlog — which is the only realistic way its authorship error rate falls as N rises.

**Single point of failure:** yes in the narrow sense that only the PM talks to the founder and
sequences rounds. That is acceptable (a coordinator is supposed to be singular) *provided* its
destructive write path is closed (W1) and its assertions about repo state are generated rather
than recalled (`state.py`). A PM that can only waste its own tokens is a bottleneck; a PM that can
destroy agent threads and rewrite history from a stale cache is a hazard. Close the second, manage
the first.

## F · In-flight scope changes

Failure 10 plus the 062→065 incident (§C) give the two shapes: an instruction narrowed while the
task ran, and a thread edited after a reader had already acted on the old text. Neither had
defined semantics, so both produced confident delivery of the wrong scope.

**Cheapest workable semantics (W5), all convention, no tooling:**

1. **A dispatched thread's original sections are immutable.** Scope changes are appended as
   `## AMENDMENT (date) — supersedes <section>` blocks. Never rewrite the Ask of a thread anyone
   may have read. (The 029-AMENDMENT incident shows amendments must be *in-file* appends, not
   sibling files — a standalone fragment broke the parser, `3248f79`.)
2. **An amendment binds a running task only when acknowledged.** Until the executing agent replies
   to it, the original scope governs. This is the definition failure 10 lacked: the race resolves
   to "the scope version the agent names in its reply," and naming it is mandatory.
3. **Replies state the scope version executed** ("worked to Ask as amended 07-27" / "original Ask;
   amendment arrived after completion"). One line. It converts the undisclosed race of failure 10
   into a disclosed, reconcilable fact the originator handles at acceptance (W6).

Cost: zero mechanism, one habit. Anything heavier (versioned frontmatter, scope hashes) solves the
same problem at higher cost — rejected.

## G · Recovery

Current exposure, measured: no remote (`git remote -v` empty), one disk, `nfl.db` is 853 MB and
**gitignored** (`.gitignore`: `data/*.db`) so it exists in exactly one copy with no history;
`data/raw/` is currently untracked (git status); ADP snapshots and mock logs are time-sensitive
captures the project's own docs call unrecoverable if lost (`CURRENT-STATE.md` Top open items 2;
data-ops agent brief). `git clean -fdx` — one agent mistake — deletes the untracked database and
raw data outright; reflog protects none of it. Parallelism multiplies exposure linearly: every
added agent is another process licensed to run git commands on the only copy.

**Minimum that makes a bad round recoverable (W8), and it is unambiguously cheaper than the
loss:**

1. A private remote, pushed at round end — or, if the founder prefers nothing off-machine, a
   scheduled `git bundle` to a second physical disk. Free; minutes to set up. This is already
   recommended in `docs/PERMISSIONS.md:61-66` and has simply not been done.
2. A nightly copy of `nfl.db`, `data/raw/`, and `data/real_drafts/` to the same second location.
   The DB is only partially reproducible from nflverse; the snapshots are not reproducible at all.
3. Keep the existing permission prompts on `rm` / `git reset` / `git clean` / `git checkout` /
   `git restore` (`PERMISSIONS.md:45-51`) exactly as they are — they are currently the *only*
   layer between an agent and unrecoverable loss, and they cost a click. Once 1-2 exist, loosening
   them for throughput becomes a defensible founder choice; today it is not.

Worktrees (W9) additionally shrink blast radius: a destructive command inside a worktree takes the
worktree.

## H · What currently costs throughput for no safety benefit?

1. **`CLAUDE.md`'s stale law** (§0, W7). Phantom agent tier, withdrawn scope, superseded build
   order — loaded first by every session, contradicted by the documents loaded second. Worry-cost
   with negative safety value, since an agent that obeys it does the wrong thing.
2. **Mandatory `status.md` narrative for every session.** The file is banned as a source of truth
   by five separate documents, so its only value is forensic narrative — yet it is a required
   serialised write for all agents, on the contention path (item 2). Keep the narrative, shard the
   file (W3): `docs/status/` with one file per session gives identical forensics with zero
   contention and no lost history. The single-file form is pure cost.
3. **PM-assigned file boundaries on code threads**, once W9 formalises worktrees — merge conflicts
   detect what boundaries prevented, without PM effort per thread. (Keep boundaries on shared-doc
   work until W3/W4 land.)
4. **The ≥100 ID range rule** — worse than no benefit; it re-arms the collision (§0.3). Delete in
   favour of W1.
5. **"Verify every line"-grade instructions on coordination docs** (failure 8). The safety content
   of that 100k-token session is now delivered by `tools/state.py` for a few hundred tokens. The
   instruction pattern — unbounded verification scope on a document — should be replaced by "run
   the generator, diff, investigate the diff."
6. **Not** on this list: one-thread-at-a-time closeout (two recorded failures justify it), the
   strategist Bash denial (the model constraint, keep), the destructive-command prompts (§G.3 —
   the last layer), and `handoffs.py check` in the test suite (it caught real rot three times in
   one day: `3248f79`, `5302fc0`).

## Explicitly accepted risks

- **Semantic contradictions beyond the crude detector.** Two threads specifying incompatible
  *designs* in different words will pass the antonym heuristic. Accepted: the 062 detector plus
  the PM's M3 pass is proportionate to one observed incident; an NLP-grade checker is over-build.
- **Duplicate threads recurring at some rate.** M3 is a discipline, not a mechanism. Accepted
  because duplicates waste a session but destroy nothing, and agent-opened threads (E) plus a
  shrinking PM authorship share attack the cause.
- **Clock skew between bridge and repo.** Fixed incidentally by W1 for new threads; historical
  `OPENED` dates stay slightly wrong. Cosmetic.
- **No CI server / no push-triggered checks.** The suite-embedded `check` runs when tests run.
  Accepted for a single-machine project; revisit only if a remote (W8) arrives anyway.
- **A malicious or deeply confused agent.** Everything here assumes good-faith agents making
  ordinary mistakes. Worktrees plus prompts plus backups bound the damage; nothing prevents it.
  Accepted — prevention would cost far more than the bounded loss.
- **The founder as final taste arbiter stays a serial dependency.** W6 reduces how often he is the
  *defect* sensor; nothing here (or anywhere) removes him as the *preference* sensor. Accepted as
  constitutive, not fixable.

## Work orders

Each is scoped for a sonnet-tier agent without further judgement. None are implemented here (per
mandate). The PM converts these to threads; suggested owner in brackets.

**W1 — Slug allocation + PM outbox** [backend, ~1 session]
In `tools/handoffs.py`: (a) `new` writes `NEW-<slug>.md` with no `ID:` field; (b) `sync` renames
any `NEW-*.md` and any file in `docs/pm-outbox/` to `{next_free_id:03d}-<slug>.md`, stamps
`OPENED:` with today's date, sets `ID:`, and hard-fails rather than overwrite an existing path;
(c) `next_id` scans filenames, not frontmatter; (d) `check` errors on any `NEW-*` file older than
one day (unfiled thread). Create `docs/pm-outbox/` with a README line saying it is the PM's only

## Stated ceiling

**After W1–W6: roughly 20–25 concurrent agents**, bounded by (a) the PM's capacity to specify
non-overlapping, well-formed asks — partially relieved by agent-opened threads but still the
serial core — and (b) the integrator's merge throughput at round end (W9), which is small per
branch but strictly serial.

**What breaks next, in order:**
1. **Acceptance bandwidth on behaviour threads** — W6 deliberately routes founder-observable work
   through one originator; at high N the DELIVERED queue backs up. The relief valve is scripted
   founder-loop smoke checks (the 063 trigger-table pattern made executable), which is the first
   thing to build *after* this batch, not in it.
2. **Semantic coordination** — with mechanical collisions gone, the residual failure is two
   threads that are individually sound and jointly incoherent (the 049/RETROFIT-5 family in
   subtler clothes). The crude detector catches the loud cases; the quiet ones remain a PM
   judgement task and scale with N.
3. **The founder himself** — taste, priorities, and league-specific truth flow through one human
   by design. FR-002 shrinks his per-item cost; N raises item count. That is the ceiling behind
   every other ceiling, and no work order moves it.
