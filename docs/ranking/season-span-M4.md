# M-4 — the season span: what it CAN be, and what it SHOULD be

**Live document. Conclusion first. Two questions, deliberately kept apart** (founder's framing,
2026-08-01): **what the span *can* be is a data fact; what it *should* be is a measured result.**
The second must not be allowed to become an argument for the status quo.

Raised by the founder, 2026-08-01, verbatim:

> "I thought we have 26 seasons of data? We don't need every one for every season. Things get added
> to models as they become available all the time. I need you and the team to stop thinking of
> excuses and know that there are clearly plenty of analysts who do this all the time. Do it the
> best we can. But there's no good reason we shouldn't be competitive."

And, on the `CLAUDE.md` §6.4 caveat:

> "Regime change is real, I agree. We should take it into account."

**He is right on the first point and the numbers are unambiguous.** v2's evaluation panel is seven
seasons because it was built on the intersection with the latest-starting sources. The core stat
lines it actually projects from run 1999–2025 with no gaps.

## 1. CAN — a data fact, measured from `nfl.db`

`experiments/bottomup/results/span_feasibility.csv`, generated by
`span_curve.py --feasibility`. A source counts as usable in a season when its volume is at least
25% of that column's own cross-season median — which catches the targets hole without anyone
hand-listing it. `earliest_first_feature_season` needs `N_LAGS = 3` clean lag seasons;
`earliest_first_target` adds `min_train_seasons = 2`.

### 1.1 The core stat lines have no gaps at all

| feature family | first season | gaps | earliest `first_feature_season` | earliest `first_target` |
|---|---|---|---|---|
| carries | 1999 | **none** | 2002 | **2004** |
| attempts | 1999 | **none** | 2002 | **2004** |
| receptions | 1999 | **none** | 2002 | **2004** |
| receiving yards | 1999 | **none** | 2002 | **2004** |
| rushing yards | 1999 | **none** | 2002 | **2004** |
| passing yards | 1999 | **none** | 2002 | **2004** |

**Twenty-one target seasons are reachable from the stat lines. v2 uses seven.**

### 1.2 Two real gaps, named rather than designed around

| feature family | first season | gaps | consequence |
|---|---|---|---|
| **targets** | 1999 | **2003–2008 are zero** | target-derived features (target share, catch rate, aDOT) support feature seasons **{2002, 2003}** and **{2012 onward}**, but not 2004–2011, because a 3-lag window straddles the hole |
| **air yards** | 2009 | 1999–2008 | aDOT / WOPR-style features cannot start before `first_feature_season` 2012 |

The targets hole is corroborated independently: `league_season_metrics.wr_target_top45_share` is
NULL for exactly 2003–2008 and populated for every other season back to 1999. **Whether this is an
ingest defect or an upstream one is not established here and it is worth establishing** — six
seasons of receiver usage history turn on it. Routed to `data-ops`.

### 1.3 The binding constraint is the ADP archive, not the football data

The evaluation universe (the M-panel) is defined by an FFC ADP board. That is the only reason the
window is seven seasons.

| evaluation tier | seasons | S | what it costs |
|---|---|---|---|
| `half_ppr_12team` ADP — **what v2 uses today** | 2018–2024 | **7** | nothing; exact format match |
| `ppr_12team` / `non_ppr_12team` ADP | 2013–2024 | **12** | a **format caveat on universe membership only** — the ADP column is never a feature and never an ordering input, so the substitution affects *which players are graded*, not what they are graded against |
| **no ADP at all** — the full-veteran-universe endpoint | 2004–2024 | **21** | a different, easier population (it includes players who score zero), so ρ levels are not comparable to the M-panel's — but it is **already computed on every cell of every batch** as `rho_points_fullvet` |

**S = 12 is the number that matters.** Strategist's own M-4 note: at S = 7 an exact season-level
randomisation test has a p-floor of 2⁻⁷ = 0.0078 and **cannot reach a BH threshold of
7.7 × 10⁻⁴ by any method**; at S = 12 it can. The 12-season tier costs a labelled format caveat on
universe membership and nothing else, and PR-009 already established that this project uses exactly
this class of caveat elsewhere (a 12-team board standing in for a 10-team league, a non-PPR ECR
standing in for half-PPR).

### 1.4 Everything else, for completeness

| source | span | earliest `first_feature_season` | binding |
|---|---|---|---|
| `league_season_metrics` | 1999–2025 | 2000 | source start |
| `depth_charts_weekly` | 2001–2024 | 2002 | source start |
| `rosters_weekly` | 2002–2025 | 2003 *(but see below)* | source start |
| `ff_opportunity` | 2006–2025 | 2007 | source start |
| `injuries`, `pbp` | 2009–2025 | 2010 | source start |
| `snap_counts` | 2013–2025 | 2014 | source start |
| `participation`, `ngs_receiving` | 2016–2025 | 2017 | source start |

**`rosters_weekly`'s nominal 2002 start is misleading and batch D1 measured why**: its
end-of-season reserve capture breaks at 2017 (prevalence 0.012–0.045 for 2012–2016 against
0.17–0.28 from 2017), so features built on it need `first_feature_season ≥ 2018` — a source's start
season is a lower bound on usability, never a guarantee of it. Every row in the table above should
be read that way. **A source-start date is a claim to be checked, not a fact to be inherited.**

### 1.5 Staggered availability is handled, not intersected

This is the founder's point and it is already the harness's behaviour: `WalkForward` takes
`first_feature_season` per run, and batches C1, C2 and D1 all use **matched controls at different
window starts** (CTRL-A 2012, CTRL-B 2015, CTRL-C 2017, CTRL-D 2018) rather than truncating
everything to the latest source. **A feature that starts in 2016 is tested on its own matched
window; it does not shorten the panel for anything else.** What has *not* been done — and is what
this document exists to fix — is running the base panel at the span its own stat lines allow.

## 2. Regime — handled, not used as a reason to truncate

`league_season_metrics` (1999–2025, 27 rows) is read by `src/ingest_league_metrics.py` and
`src/db.py` and **by no model** — the same pattern as `injuries` and `depth_charts_weekly`. It
quantifies the structural shift directly:

| | 1999 | 2012 | 2024 | 2025 |
|---|---|---|---|---|
| `te_point_share` | 0.0956 | 0.1329 | 0.1298 | **0.1452** |
| `qb_point_share` | 0.2019 | 0.2120 | 0.2272 | 0.2248 |
| `rb_carry_top30_share` | 0.679 | 0.612 | 0.598 | 0.589 |
| `wr_target_top45_share` | 0.582 | 0.540 | 0.522 | 0.530 |
| `points_per_team_game` | 20.81 | 22.76 | 22.91 | 23.01 |
| `neutral_pass_rate` | 0.497 | 0.505 | 0.511 | 0.509 |

**What is already neutralised, and must not be fixed twice.** The evaluation metric is a
**within-season** rank correlation, so pure scoring-level inflation — `points_per_team_game` rising
10% across the span — is already handled and normalising for it again would be double-counting.
**What is not handled is structural change**: positional point shares and workload concentration,
which change *who* the fantasy-relevant players are, not just how much everyone scores.

**The `ctx` variant therefore normalises structure, not level.** Each era-sensitive feature is
divided by its own lag-weighted league-season norm — the same `LAG_WEIGHTS` the feature itself uses,
applied to the same three seasons' metrics — and re-expressed relative to 2024 so scales are
unchanged. It is arithmetic on a published table: **no fitted parameter, nothing to overfit.**

Two metrics are deliberately **not** used as normalisers: `rb_carry_top30_share` and
`wr_target_top45_share` are NULL across 2003–2008, the same gap as the targets feature they would
normalise. A normaliser sharing its feature's gap reintroduces the gap as a time dummy — batch 7's
D2 finding — so they are excluded and that exclusion is recorded rather than discovered later.

**No decay profile is fitted here.** Recency weighting is the second lever, not the first, and it
belongs to strategist's live pre-registration
(`docs/preregistration/PR-DRAFT-lag-weight-decay-profile.md`). `span_curve.py` touches
`LAG_WEIGHTS` only to read it.

## 3. SHOULD — the measured curve

**Design.** Vary `first_feature_season` over {2002, 2006, 2010, **2012 = incumbent**, 2015, 2018}.
**Hold the target seasons fixed at 2018–2024 for every span**, so each span is scored on the
identical evaluation set and the curve is a curve. Extending the target window at the same time
would move the training set and the evaluation set together and the two effects would be
inseparable. Two variants per span: `raw` and `ctx`. Model is the pinned v2 control (games arm G0),
unchanged; nothing but the window and the normalisation differs.

Endpoints, per position, paired by season against the incumbent 2012 span:

- `rho_points` — M-panel board veterans, the ADR-069 absolute steering metric
- `rho_points_fullvet` — full veteran universe, **needs no ADP**
- `rho_games` — the availability channel

**A known confound, stated in advance of the numbers:** the 2003–2008 targets hole means WR and TE
spans starting at 2002, 2006 or 2010 include training rows whose target-derived lag features are
structurally zero. Any decline there is a **data defect, not a regime finding**, and must not be
reported as evidence that older seasons are misleading. **QB and RB are the clean measurement** —
their volume channels (attempts, carries) have no gap.
